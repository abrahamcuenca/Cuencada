# WP-5.1 Past Cuencadas: undated past status, historical editions, "Agregar Cuencada anterior"
Owner: Senior full-stack JS · Branch: `wp/5.1-past-cuencadas` · PR: # (not opened)

Based on `origin/main` (`8147363`, WP-4.7 merged). Migration **`0007`** (expand-only). WP-5.2 (events, migration `0008`) runs in parallel; this WP touches no chat or media schema.

## Why
Creating a past Cuencada already worked (Panel → Cuencadas → "＋ Nueva" accepts any year and past dates), but `computeCuencadaStatus` labelled every published edition without dates as `announced`. So a "2019, dates unknown" edition was missing from Home's "Cuencadas anteriores", showed "Por anunciar" on its page, and got a chat room when published.

## What changed
### Status (`apps/server/src/modules/cuencadas/status.ts`)
`StatusInput` gains `year` and `isHistorical` (the DB row already has both). The order of the rules:
1. unpublished → `draft`;
2. **historical → `past`**, whatever its dates say;
3. undated → **`past` when `year` is before the current year in the edition's timezone**, otherwise `announced` (so a 2026 announcement rolls over to `past` at local midnight on 1 January 2027);
4. dated → `upcoming` / `active` / `past` by calendar day, as before.

`selectHome` sorts past editions with the new exported `comparePastNewestFirst`: by `endsAt`, and for an undated edition by the last millisecond of its `year` (UTC), with `year` (descending) as the tiebreaker. `latestPast` therefore includes undated past editions. Home's "Cuencadas anteriores" (`status === "past"`, server order newest year first) picks them up with no web change.

### Migration `0007_historical_editions.sql`
`cuencadas.is_historical boolean not null default false`. It is generated by drizzle-kit, and only comments were added. It is expand-only: a constant default, no rewrite (PG 11+), no data step. 0006-era code never names the column. There is **no DB CHECK** for "year before the current year", because that depends on now, so the API enforces it.

### Contracts (`packages/types/src/cuencadas.ts`)
- `isHistorical?: boolean` on `CuencadaSummary`, `PublicCuencada` and, through it, `AdminCuencada`. It is optional in responses (`exactOptional`), so older clients and servers keep parsing. The server always sends it.
- `isHistorical: boolean` in the admin input fields: create defaults to `false`, and PATCH only changes it when it is sent.
- `CUENCADA_HISTORICAL_YEAR_MESSAGE` = "Una Cuencada anterior debe ser de un año pasado."

### Historical editions (server)
- **Validation:** `POST` and `PATCH /api/admin/cuencadas` answer 400 `VALIDATION` (detail on `year`) when the merged row is historical and `year >= localYearInZone(now, timezone)`. A PATCH checks the merged flag, year and timezone, so moving a historical draft to this year is refused too.
- **No chat room:** `ensureCuencadaChatRoom` returns `false` for a historical edition, and the `cuencada.published` audit records `chatRoomCreated: false`. If a published edition is later un-flagged, the PATCH creates the room it skipped (idempotent).
- **No RSVP:** `RsvpEditionInput` now extends `StatusInput`. A historical edition is `past`, so `rsvpEditability` refuses with the existing `past` reason (409 "Esta Cuencada ya pasó…"). An undated edition of an earlier year is also `past` now (it used to answer `dates_pending`).
- **Never the Home hero:** it is always `past`, so it can only ever be `latestPast`. A test covers a historical row whose dates would make it `active`.

### Decision: an existing chat room of an edition later marked historical
The room is **kept** (never deleted: its history stays) but **hidden everywhere**. `visibleRoomSql` (chat repository) now requires `is_published and not is_historical`, the same treatment an unpublished edition's room already gets. So it disappears from `GET /api/chat/rooms`, answers 404 by id (history, read, message delete) and is refused on the socket. Un-flagging the edition makes it visible again. I chose "hidden everywhere" over "only not listed" because a room that is unlisted but still writable by id would be an inconsistent half state.

### Admin UI (`apps/web/src/features/cuencadas/admin`)
- `AdminCuencadasPage`: "＋ Nueva" and a secondary "＋ Agregar Cuencada anterior" (they wrap on a phone).
- `components/PastCuencadaForm.tsx` ("Cuencada anterior"):
  - **year:** 4 digits, ≥ 1900 and before the current year in Mérida (the server says the same); the title defaults to "Cuencada {año}"
  - **description:** required
  - **city/state:** optional
  - **"Primer día" / "Último día":** optional calendar days, hint "Si no recuerdas las fechas exactas, déjalas vacías". They are sent as 00:00 and 23:59 in America/Merida with that date's offset (Mérida observed summer time until 2022). It's both days or neither, and the last day can't be before the first.
  - **"Imagen de portada":** an optional URL (the upload comes with WP-5.4)

  It is sent as `isHistorical: true, isPublished: true`.
- After saving, a "Cuencada {año} agregada" card links to **Asistencia** (`/admin/cuencadas/:id/asistencia`), **Fotos** (`/galeria/{año}`) and **Editar detalles**.
- The list marks historical editions with an "Anterior" badge. An undated past edition reads "Fechas desconocidas" and "Lugar sin registrar" instead of "por anunciar". The edit page shows "Cuencada anterior al portal: sin confirmaciones ni chat."
- `CuencadaFormBody` now omits `isHistorical`, so saving the regular edit form never resets the flag. There is no UI to un-flag an edition (it can be done through the API); see the backlog.

### Year page (`CuencadaYearPage`)
- **Historical:** the hero shows "Esta Cuencada ocurrió antes del portal." (`data-testid="historical-note"`) instead of a countdown or "Por anunciar". The programa and places sections are hidden unless they have items, even when dates are set.
- **Any undated past edition:** the kicker is "{Ciudad · Estado ·} {año}" (`formatPastKicker`), never "Fecha y lugar por anunciar". A non-historical one says "La Cuencada {año} ya es parte de nuestra historia."
- The members block already handles `past`: "¿Quién fue?" and no RSVP form.

### Gallery year switcher
The switcher **already listed every published edition** (`galleryYearsFrom` maps all of `GET /cuencadas`; `hasMedia` only picks the default year), so the plan's finding was stale. The only change is to the default year: a `past` edition counts as started even without dates, so an undated past year can be the default when nothing newer has started. The order stays newest year first. The gallery test fixture `makeEdition` now derives `status` from its dates (it called a 2099 edition `past`).
